# 마비노기 모바일 시즌2 격투가 DPS 계산기

[공개 계산기](https://payongaleul.github.io/MobiNogi-fighter-season2/)는 **마비노기 모바일 시즌2 격투가**의 현재 입력값을 기반으로 실전 가중 DPS를 계산하는 정적 웹 애플리케이션입니다. React·Vite 기반으로 브라우저에서 동작하며, 서버·인증·외부 비밀을 사용하지 않고 GitHub Pages에 배포됩니다.

> 이 프로젝트는 저장된 DPS를 재표시하지 않습니다. 마을 상태창, 룬·초월·세공·인장, 전투 대상, 마도저항, 조건부 가동률, 스킬 스탠스, 딜사이클을 입력으로 받아 매번 다시 계산합니다. 정상·궁극기 사이클이 비었거나 해석되지 않으면 기본 사이클을 대입하지 않고 해당 상태를 **0 DPS**로 처리합니다.

## 입력과 계산 계약

### 상태창 완료값 원칙

마을 공격력은 음식·일시 버프가 없는 인게임 상태창의 완성값입니다. 전설 패션 세트, 동행 펫, 달의 인장, 장착 룬의 **고정 공격력·고정 능력치**가 상태창에 이미 포함되었다면 계산 코어가 다시 더하지 않습니다.

적용 공격력은 다음 계약을 사용합니다.

```text
적용 공격력 = 마을 공격력 × (1 + 선택 룬의 상시 공격력% 합계 + 인챈트 공격력%)
```

상시 공격력%에는 조건부 가동률이나 초월 배율을 다시 곱하지 않습니다. 조건부 공격력 증가는 별도 효과 ID와 가동률을 가진 `조건부공증%`로 모델링합니다. 기본 가동률은 **흐릿한 형상 70%**, **타오르는 영광 13%**이며, 사용자 입력으로 조정할 수 있습니다.

### 룬 효과 모델 v2

효과 모델 v2는 **43개 룬**에 적용되어 상시 스탯을 100%로 적용하고 조건부 효과만 독립적으로 조정합니다. 이 범위에는 공격·적중·스킬·궁극기 트리거, 지속/재사용 대기시간, 중첩, 조건부 공격력, 대상 방어구 파괴, 직접 피해·도트, 침식·용의 문장·신화 룬의 장착 조합 효과가 포함됩니다. 저장 키는 `runeId:effectId`가 우선이며 이전 `룬명:effectId`, `룬명` 입력은 읽기 호환합니다. 따라서 승전의 상시 `주는 피해 5% / 치명타 피해 10%`는 룬 단위 가동률 입력으로 3%처럼 축소되지 않습니다.

시간축 엔진은 효과의 지속 시간, 재사용 대기시간, 이벤트 빈도, 중첩, 직접 피해, 도트 틱 간격을 분리해 평균 스탯과 초당 피해를 계산합니다. `forceDefaultUptime`은 현장 검증 기본값이 내부 주기보다 우선해야 할 때 사용하며, `damageIntervalSeconds`와 `damageScalesWithUptime`은 활성 기간에만 반복되는 피해를 별도로 계산합니다. 조건부 가동률이 1이 아닌 효과는 전투 설정에서 조절할 수 있으며, 외부 상태·처치·저체력·장착 조합처럼 자동 판단할 수 없는 조건은 **0%를 임의 확정하지 않고 기본값 0%의 수동 입력**으로 노출합니다. 속도·재사용 회복은 해당 채널로 보존하며 근거 없이 임의 DPS 배율로 합산하지 않습니다. 88개 전체의 문장 감사 인벤토리와 현재 모델 상태는 `results/rune_sentence_inventory.md`에 기록합니다.

마도저항도 장비와 장착 룬이 반영된 **상태창 완료값**입니다. 선택 룬의 고정 마도저항을 코어가 다시 합산하지 않아 중복 가산을 막습니다.

### 딜사이클과 연속 인스턴스

새 입력 문법은 같은 번호의 스킬을 연속으로 적었을 때 첫 번째 `1`을 `1-1`, 다음 `1`을 `1-2`처럼 순차 정규화합니다. 기존 저장 프리셋은 `legacy-v1` 문법으로 보존하여 과거 비교값이 임의로 바뀌지 않게 합니다. 강격 섬머솔트의 기본 시전 시간은 2초이며, 승천 소닉 피스트의 기대 시전 시간은 2.584초입니다.

## 현행 전투 대상과 보정 범위

필요 마도저항·마도압력은 넥슨 공식 난이도 표를 사용합니다.[1] [2] 방어도·치명타저항은 공식 공개 수치가 없으므로, 아래 값은 기존 함께하기·신규 혼자하기·함선 참조를 합친 23건의 비식별 기록을 재평가한 **P2-B 로그 기반 공통 근사치**입니다. 공식 스탯으로 해석하면 안 되며, 계산기와 UI에서 `낮은 신뢰도`로 명시합니다. 기록 총수는 후보 범위 검증을 보강하지만, 대상별로 상태창·장비·세공·프리즘·인챈트·증폭·딜사이클·무방비/브레이크를 통제한 반복은 없으므로 혼자하기 후보를 별도 데이터로 분리하거나 현행 수치를 대체하지 않습니다.

| 대상 | 필요 마도저항 | 마도압력 | 적용 방어도 | 방어도 80% 근사 범위 | 적용 치명타저항 | 로그 표본 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 함선 허수아비 | 0 | 0 | 30 | 훈련 기준값 | 0.0% | 해당 없음 |
| 티르코네일 허수아비 | 0 | 0 | 30 | 훈련 기준값 | 0.0% | 해당 없음 |
| 허상의 정박지 · 매우 어려움 | 2,200 | 2,700 | 8,408 | 6,561–10,255 | 0.0% | 2 |
| 광기의 동굴 · 매우 어려움 | 2,200 | 2,700 | 17,125 | 15,646–18,605 | 0.0% | 2 |
| 흩어진 물길 · 매우 어려움 | 2,200 | 2,700 | 18,967 | 16,261–21,674 | 0.0% | 2 |
| 카브락 레이드 · 입문 | 2,000 | 2,500 | 7,203 | 7,039–9,542 | 0.0% | 3 |

룬다 어비스 매우 어려움 3종은 필요 마도저항과 마도압력은 같지만, 기존 로그 기반 공통 방어도 모델의 최대 방어계수 잔차가 **35.7%**이고 개별 근사 범위의 공통 교집합도 없었습니다. 총 23건 재평가에서도 각 던전의 통제된 반복은 확보되지 않아 이 결론을 바꾸지 않았습니다. 따라서 세 던전을 하나의 `매우 어려움` 선택지로 축소하지 않고, 전투 조건에서 각각 분리해 둡니다. 다만 일반 UI에서는 보스명이 아니라 **던전명·난이도·필요 저항·압력**만 표시합니다. 어비스 잡몹방은 평타 대조 로그가 없어 보스룸과의 방어도·치명타저항 차이가 **미확정**입니다.

### 마도저항 보정

넥슨 가이드는 마도저항이 마도압력보다 낮으면 주는 피해가 감소하고 받는 피해가 증가하며, 같거나 높으면 페널티가 없고, 초과 시 적에게 입히는 최종피해가 증가한다고 안내합니다.[3] 공개된 초과 예시점만 아래와 같이 반영합니다. 미달 시 정량 피해 계수와 초과분의 완전한 연속 함수는 공개되지 않았으므로 임의로 추정하지 않습니다.

| 마도저항 초과분 | 최종피해 증가 | 계산기 처리 |
| ---: | ---: | --- |
| 0 | 0.0% | 공식 기준점 |
| 500 | 4.1% | 공식 예시점 |
| 1,000 | 7.9% | 공식 예시점 |
| 2,000 | 14.6% | 공식 예시점 |
| 4,000 | 25.0% | 공식 예시점 |
| 8,000 이상 | 37.5% 고정 | 이후 비공개 연속식은 추정하지 않음 |

예를 들어 카브락 입문에서 상태창 마도저항이 4,500이면 마도압력 2,500보다 2,000 높으므로, 대상 방어도·치명타저항을 반영한 결과에 최종피해 배율 `1.146`을 한 번 적용합니다.

## 계산 구조

계산과 화면 렌더링은 논리적으로 분리돼 있습니다.

| 계층 | 주요 경로 | 책임 |
| --- | --- | --- |
| 순수 계산 코어 | `src/core/` | DPS, 보석, 인장, 마도저항, 대상 보정. React·DOM·localStorage 의존 없음 |
| 애플리케이션 어댑터 | `src/adapters/` | 룬 평탄화, 세공 집계, 스킬 원문 파싱, 입력 조립, 기존 저장값 호환 |
| UI·데이터 | `src/components/`, `src/data/` | React 입력·표시, 정적 룬/대상 데이터, 접근성·반응형 UI |

계산 결과는 적용 공격력, 마도저항/압력, 마도저항 최종피해, 대상 방어도, 대상 치명타저항, 룬 공격력 가산, 치명타·추가타 확률을 함께 보여 줍니다. 렌더러는 계산식을 직접 수행하지 않고 어댑터의 결과만 소비합니다.

## 로컬 실행과 품질 검증

### 실행

```bash
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:5173/MobiNogi-fighter-season2/`입니다.

### 필수 품질 관문

계산 엔진, 룬 파서, 인장·보석 계산, 대상 데이터 또는 UI를 바꾸면 다음을 순서대로 실행합니다.

```bash
npm run lint
npm run test:coverage
npm run build
node scripts/compare_latest_reference_presets.mjs
node scripts/ux-ui-check.mjs
npm run test:e2e
```

커버리지 임계값은 Statements·Branches·Functions·Lines 각각 **95%**입니다. 현재 전체 검증에서는 **139개 테스트**가 통과했고, Statements 99.09%, Branches 96.25%, Functions 100%, Lines 99.50%를 기록했습니다. 린트는 오류 0건으로 통과했으며, 500 kB 청크 경고는 기존 번들 크기 안내로 기능 오류가 아닙니다.

최신 원문을 재대조해 **아귀의 ‘무방비 피해 12%’가 주는 피해·콤보 피해로 잘못 중복 매핑된 오류를 정정**했고, 5초 직접 피해·상처를 시간축 초당량으로 반영했습니다. canonical 룬 기준선과 실제 UI 어댑터를 참조 프리셋 비교에도 동일하게 사용합니다. 현재 5개 참조 프리셋의 모델 편차는 **-3.97%, +0.64%, +3.05%, -2.33%, +0.75%**이며, 모든 기록이 ±10% 기준 안에 있고 평균 절대 편차는 **2.148%**입니다. 적용 공격력 골든 계약은 마을 공격력 60,607 입력 시 105,638이 되는 회귀값을 유지합니다.

## 재현 가능한 로그 근사 분석과 개인정보

`scripts/analyze_p2b_calibrated_targets.mjs`는 로컬의 `results/p2b_raw_logs/`에 보관한 기존 기록을 읽어 대상별 방어도·치명타저항 후보, 부트스트랩 80% 근사 범위, 룬다 어비스 공통 모델 판정을 생성합니다. `scripts/analyzeNewPrivateDpsLogs.mjs`는 별도 로컬 경로의 신규 혼자하기 기록을 읽어 보스룸 평타·스킬 로그 후보와 치명타 관측 구간을 생성하되, 표본 부족 시 자동으로 **채택 보류**를 보고합니다. `scripts/analyzeDpsLogEvidence.mjs`는 두 자료군과 함선 참조를 유효 독립 표본 기준으로 재분류해 기록 총수와 실제 식별 근거를 구분합니다.

```bash
node scripts/analyze_p2b_calibrated_targets.mjs
node scripts/analyzeNewPrivateDpsLogs.mjs
node scripts/analyzeDpsLogEvidence.mjs
```

원본 기록 JSON에는 개인 전투 상세와 장비 정보가 포함될 수 있으므로 Git에서 제외합니다. 저장소에는 재현 스크립트와 비식별 분석 결과만 보관합니다. 분석 방법·로그별 후보·한계는 [P2-B 로그 기반 근사 보정 분석](results/p2b_calibrated_target_estimates.md), [신규 1인 로그 후보 분석](results/new_private_log_candidate_estimates.md), [DPS 로그 증거력 재평가](results/dps_log_evidence_reassessment.md)에서, 현행 대상·마도저항 데이터 계약은 [P2-C 구현 계약](docs/P2C_CURRENT_TARGETS_AND_MAGIC_RESISTANCE.md)에서 확인할 수 있습니다.

## 배포

`main` 병합 후 GitHub Actions가 린트·커버리지·빌드·E2E를 실행하고, 성공한 정적 산출물만 GitHub Pages에 배포합니다. 공개 배포본의 최신 화면 검증 기록은 [P2-C 렌더링 검증 기록](results/p2c_render_verification.md)에 보존합니다.
