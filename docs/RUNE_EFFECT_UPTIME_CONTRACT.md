# 시즌2 룬 효과·가동률 데이터 계약

**상태:** P2-D 정책 기록·v2 1차 구현 기준
**권위 원문:** `results/260814_룬설명목록.md` — SHA-256 `A86E44F39200A2872DD15A9C8B2C577B2EAA052F6BF9476B5A2254D61908B93A`
**수정 금지:** 권위 원문의 문구·수치·룬 이름은 자동 정규화나 파서 보정으로 변경하지 않는다.

> **우선순위 규칙:** 최신 권위 원문의 룬 이름·효과 문구·명시 수치가 `runes.json`의 기존 OCR·수동 보정·감사 별칭보다 우선한다. 예를 들어 원문 표기가 **그믐달**이면 데이터·UI·감사 결과도 그믐달을 사용한다. 기존 오타 `그음달`은 읽기 호환 별칭만 될 수 있으며 정식 표기가 아니다.

## 1. 효과 모델

각 룬은 상시 효과와 조건부 효과를 반드시 분리한다. 룬 전체에 단일 가동률을 곱해 상시 효과까지 줄이는 방식은 금지한다.

```json
{
  "id": "armor-conqueror-plus",
  "name": "정복자+",
  "stats": {
    "공격력%": 0.05,
    "주는피해%": 0.09
  },
  "conditionalEffects": [
    {
      "id": "nearby-kills-crit-damage",
      "label": "주변 처치 치명타 피해",
      "source": "주위에서 적이 5/10/20명 처치될 경우, 치명타 피해가 3%/6%/12% 증가한다.",
      "stats": { "치명타피해%": 0.12 },
      "defaultUptime": 0.0,
      "uptimeStep": 1,
      "modelStatus": "manual",
      "triggerScope": "nearbyKill"
    }
  ],
  "mechanics": {
    "attackSpeedPct": 0,
    "skillUseSpeedPct": 0,
    "castChargeSpeedPct": 0,
    "directDamage": []
  }
}
```

| 필드 | 계약 |
| --- | --- |
| `id` | 저장·테스트·효과 키에 쓰는 안정 식별자다. 표시명·번역·줄바꿈으로 바꾸지 않는다. |
| `stats` | 조건 없이 지속되는 상시 수치다. **항상 100% 적용**하며 전투 설정 가동률 UI에 노출하지 않는다. |
| `conditionalEffects[].id` | 룬 내부에서 불변인 효과 식별자다. 수동 override 키는 `runeId:effectId`를 사용한다. |
| `conditionalEffects[].stats` | 해당 조건을 만족할 때만 적용되는 수치다. `defaultUptime` 또는 효과별 override로만 곱한다. |
| `defaultUptime` | 0~1의 기본 기댓값이다. 효과별로 독립 저장한다. `1`이면 기본 UI에서 숨기되 계산은 적용한다. |
| `modelStatus` | `modeled`, `manual`, `unresolved`, `notApplicable` 중 하나다. `unresolved`는 DPS에 임의 숫자로 넣지 않는다. |
| `mechanics` | 공격 속도·스킬 사용 속도·캐스팅/차지 속도·직접 피해 등 별도 계산 정책이 필요한 정보를 원문 그대로 보존한다. |

## 2. 가동률 및 호환 규칙

기존 `stats.가동률`과 `conditionalUptimes[룬이름]`은 룬 전체 통계에 적용하면 안 된다. P2-B에서는 다음 우선순위를 사용한다.

1. `conditionalUptimes["runeId:effectId"]`가 있으면 그 값을 사용한다.
2. 없으면 읽기 호환 키 `conditionalUptimes["룬이름:effectId"]`를 사용한다.
3. 없으면 레거시 `conditionalUptimes[룬이름]`를 사용한다.
4. 위 키가 모두 없을 때만 해당 효과의 `defaultUptime`을 사용한다.
5. 상시 `stats`는 어떤 가동률 override에도 영향을 받지 않는다.

이 규칙으로 상시 주는 피해 9%, 치명타 피해, 재사용 대기시간 회복 속도 등은 3%처럼 축소되지 않는다.

## 3. 속도 및 기본 공격 경계

원문 속도 문구는 다음 세 채널로 분리 보존한다.

| 채널 | 예시 | 현재 DPS 반영 |
| --- | --- | --- |
| `attackSpeedPct` | 공격 속도, 기본 공격 속도 | **미반영**. 쿨다운 공백 기반 평타 이벤트 모델 확정 전에는 DPS에 추정값을 넣지 않는다. |
| `skillUseSpeedPct` | 스킬 사용 속도 | 기존 엔진 정책·근거가 검증된 경우에만 반영한다. |
| `castChargeSpeedPct` | 캐스팅 및 차지 속도 | 스킬 시전시간에 적용하기 전 스킬별 적용 범위를 테스트로 고정한다. |

격투가의 평타는 스킬마다 1회 자동 삽입되는 공격이 아니라 스킬 쿨다운 공백을 메우는 필러 행동이다. 현재 엔진에는 실제 쿨다운 준비 시점·평타 1회 시간·피해·적중 트리거가 없으므로 기본 공격 관련 룬은 `modelStatus: unresolved`, `includedInDps: false`, `impact: N/A`로 유지한다.

## 4. 직접 피해 및 도트 경계

룬의 직접 피해·범위 피해·도트는 다음을 각각 명시하기 전까지 DPS에 추정 반영하지 않는다.

1. 발동 조건·주기·쿨다운·중첩·대상 수
2. 치명타·방어도·마도저항·무방비 적용 여부
3. 스킬 피해·주는 피해·강타/연타·최종 피해와의 상호작용
4. 딜사이클 시간에 들어가는지 여부

원문과 테스트로 위 항목이 확정되면 별도 `directDamage` 이벤트로 모델링한다. 현행 전역 `directDps`에 임의로 합산하지 않는다.

## 5. UI와 테스트 계약

전투 설정에는 `defaultUptime !== 1`인 `modeled`·`manual` 효과만 노출한다. 각 카드는 룬 이름, 효과 이름, 원문 근거, 기본 가동률, 현재 override를 보여야 한다. `unresolved` 효과는 숫자 슬라이더 대신 "계산 미반영" 상태와 사유를 보여야 한다.

테스트는 최소한 다음을 보장한다.

- 상시 `주는피해 9%`와 `재사용회복%`은 룬 가동률 0~100% override에 영향받지 않는다.
- 효과별 override는 같은 룬의 다른 효과와 상시 효과를 바꾸지 않는다.
- 흐릿한 형상 70%, 타오르는 영광 13% 기준은 변하지 않는다.
- 기본 공격 속도는 스킬 시전시간·스킬 피해·전역 DPS에 곱해지지 않는다.
- 원문 정식 명칭 그믐달이 UI·데이터·감사 보고서에 표시된다.

## 6. 전수 대조 적용 현황

`results/rune_effect_policy_matrix.md`는 권위 원문 88개와 현재 계산 데이터 88개를 이름 기준으로 전수 대조한 정책 매트릭스다. 이 문서의 상태는 모델 구현 범위와 미확정 메커니즘을 명시하기 위한 것이며, 원문에 근거 없는 DPS 보정값을 만들어 넣지 않는다.

| 구분 | 현재 처리 | 이유 |
| --- | --- | --- |
| 효과 모델 v2 | 오랜 광기, 억눌린 충동, 거대한 분노, 바위 칼날, 두 갈래 별, 추적자, 첫 번째 서약, 아귀, 정복자+, 은빛 찬가, 승전 | 상시 수치·효과별 가동률·미확정 이벤트를 분리했다. |
| 레거시 v1 조건부 | 57개 | 기존 참조 DPS·사용자 검수 수치를 유지하고, 개별 발동/쿨다운/스택 근거가 확정되기 전 신규 기댓값을 가정하지 않는다. |
| 상시·기존 수치 | 20개 | 현행 수동 보정과 계산 계약을 그대로 적용한다. |

> 전수 대조의 완료는 **88개 이름·원문 감사 코드·현재 적용 정책을 모두 기록했다**는 뜻이다. 아직 `unresolved` 또는 `v1 동결`인 직접 피해, 평타/적중 이벤트, 속도 채널, 스택/쿨다운 효과는 확정된 게임 메커니즘과 딜사이클 이벤트가 확보된 별도 작업에서만 DPS 수치로 승격한다.
