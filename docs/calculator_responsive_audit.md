# 실제 사용자 브라우저 기반 종합 계산기 UI 감사 — 1차 관찰

## 관찰 환경

공개 GitHub Pages를 연결된 사용자 브라우저에서 열어, 저장된 실제 설정이 적용된 종합 계산기 화면을 확인했다. 현재 사용자 브라우저의 데스크톱 뷰에서는 화면 아래에 약 323px의 추가 스크롤 영역이 남아 있었다.

## 확인된 강점

상단 제목·테마 전환·탭은 한 줄 헤더로 정리되어 있고, 좌측 입력 영역과 우측 실전 DPS·룬 세팅·세부 연산 보드의 큰 정보 구조가 즉시 구분된다. 실전 DPS는 문서 흐름의 우측 상단에 유지되며, 전투 설정의 독립 진입점도 화면 좌측에서 발견 가능하다. 실제 장착된 룬 상태가 있는 화면에서 5×2 룬 배치와 초월 조작이 보드 안에 함께 표시되는 점도 확인됐다.

## 개선 기회

| 우선순위 | 관찰한 문제 | UX 영향 | 개선 가설 |
| --- | --- | --- | --- |
| 높음 | 좌측 기본 스펙 8개, 개조 단계 6개, 시즌 패시브 3개가 모두 작은 글자·작은 컨트롤로 밀집되어 있다. | 수치·보조 설명을 읽기 어렵고, 숫자 입력 및 증감 조작에서 오입력 가능성이 높다. | 카드 수를 무조건 줄이지 않고, 핵심 4개와 보조 4개를 시각적으로 군집화한다. 입력값은 유지하되 레이블·수치의 최소 글자 크기와 버튼 터치 영역을 키운다. |
| 높음 | 오른쪽 룬 5×2 카드에는 룬 이름, 효과, 제거, 초월 3단계가 동시에 들어가며 장착 효과가 긴 경우 줄 수가 많아진다. | 작은 글자와 버튼 과밀로 룬 상태 파악·초월 변경의 정확도가 떨어진다. | 카드별 상태 정보는 유지하고, 상시 표시할 효과 텍스트를 한 줄 요약으로 정규화한다. 상세 수치는 접이식 룬 효과 사전에서 보완한다. 초월 단계는 세그먼트 컨트롤의 최소 폭을 보장한다. |
| 중간 | 우측 DPS 결과 보드와 4개 보조 지표는 읽기 쉽지만 결과 카드의 안내·상태 텍스트가 별도 줄을 차지한다. | 결과 영역이 조금 높아져 아래 세부 연산·프리셋 가시성이 감소한다. | 상태 문구·안내를 결과 헤더 또는 수치 옆 보조 정보로 통합하고, 핵심 DPS 숫자와 4개 지표의 가독성은 유지한다. |
| 중간 | 전투 상황 및 딜사이클 보드는 기본 스펙·패시브 아래에 남아 있어 첫 화면에서 하단으로 밀린다. | 사용자는 보스·시간·사이클이 DPS 필수 입력임을 알지만 즉시 확인하기 어렵다. | 전투·딜사이클 중 자주 바꾸지 않는 부가 설명 및 보조 설정을 전투 설정 바 후보로 검토한다. 보스와 시간·사이클처럼 계산 필수인 핵심 입력은 본문에 남긴다. |
| 중간 | 전투 설정 바의 세로 탭은 발견 가능하지만, 바 안에 포함된 설정의 현재 요약 상태가 닫힌 상태에서 제한적으로 드러난다. | 조건부 가동률·스탠스 상태를 놓칠 수 있다. | 전투 설정 탭에 ‘스탠스 5개 설정됨’, ‘조건부 룬 n개’ 같은 짧은 상태 요약을 추가할지 평가한다. |

## 반응형 재점검 항목

모바일에서는 현재 데스크톱의 고밀도 카드 구조를 그대로 축소하지 않도록 다음을 최우선으로 확인해야 한다. 첫째, 헤더·탭은 수평 스크롤 없이 접근 가능해야 한다. 둘째, 숫자 입력·증감 버튼·토글·룬 초월 버튼은 터치 영역이 유지되어야 한다. 셋째, 실전 DPS와 전투 설정 진입점은 첫 화면에서 명확해야 한다. 넷째, 긴 룬 효과 텍스트와 보스 선택값은 잘림 대신 자연스러운 줄바꿈 또는 요약·상세 구조를 사용해야 한다.

## 현 단계 결론

추가 압축은 가능하지만, 단순히 패딩·글자 크기를 더 줄이는 방식은 사용자 목표인 가독성과 조작감을 해칠 위험이 크다. 다음 단계에서는 실제 컴포넌트의 반응형 클래스와 카드 구조를 대조한 뒤, ‘작은 글자를 키우면서도 첫 화면 가시 영역을 늘리는’ 재배치 중심의 개선안만 새 브랜치에서 구현한다. main 병합과 배포는 수행하지 않는다.

## 전투 설정 바 실제 관찰

사용자 브라우저에서 전투 설정 바를 열어 확인한 결과, 스탠스 5개와 조건부 룬·밤의 축복 가동률이 전투 문맥으로 모여 있어 기능 분류 자체는 적절했다. 다만 약 390px 폭의 바 안에서 섹션 제목, 도움말, 스탠스 레이블, 선택 컨트롤, 조건부 효과 설명, 슬라이더의 본문·보조 글자가 모두 작게 보인다. 따라서 본문에서 부가 설정을 추가 이동하기 전, 사이드바 내부의 최소 글자 크기와 행 높이를 먼저 개선해야 한다.

부가 기능 이동 후보는 ‘스킬 약어 안내’와 ‘같은 번호 스킬 반복 입력 규칙’처럼 딜사이클을 처음 수정할 때만 필요한 도움말이다. 이 정보는 전투 설정 바의 접이식 ‘입력 도움말’ 또는 본문의 짧은 아이콘 도움말로 옮길 수 있다. 반면 보스 선택, 평상시·궁극기 시간, 일반·궁극기 사이클은 DPS 계산의 핵심 편집 요소이므로 본문에 남겨야 한다.

## 선택한 개선 범위

이번 브랜치에서는 단순히 여백을 더 줄이지 않는다. 다음 개선을 함께 적용한다.

| 구역 | 선택 개선 | 이유 |
| --- | --- | --- |
| 모바일 정보 위계 | 모바일에서는 실전 DPS 결과를 기본 스펙 카드보다 먼저 배치한다. | 첫 화면에서 결과와 계산 상태를 즉시 확인하게 한다. 데스크톱의 우측 결과 배치는 유지한다. |
| 기본 스펙·개조 | 핵심 스탯 카드의 레이블·입력값·슬라이더 여백을 키우고, 개조 단계는 일반 데스크톱에서 3열·초광폭에서만 6열로 전환한다. | 실제 1560px 화면에서 과도한 6열 압축을 해소하면서, 2560px 시안형 밀도는 유지한다. |
| 룬 카드 | 이름·효과 요약·초월 단계의 최소 글자 크기와 버튼 높이를 키운다. | 실제 장착 효과와 초월 선택을 실수 없이 읽고 누르게 한다. |
| 전투 설정 바 | 스탠스 행과 조건부 가동률 카드의 글자·선택 컨트롤을 키우고 바 폭을 소폭 넓힌다. | 부가 기능의 적절한 수용 공간을 먼저 확보한다. |
| 전투 도움말 | 반복 스킬 규칙·약어 설명은 접이식 도움말로 바꾼다. | 필수 입력을 남기면서 기본 화면의 세로 밀도를 개선한다. |
| 섹션 안내 | 시각적 섹션 제목은 키우고, 중복되는 장문 설명은 화면상에서 숨긴다. | 정보 위계는 강화하고 불필요한 세로 점유는 줄인다. |

추가 인챈트, 보스·시간·사이클, 시즌 패시브는 이번 변경에서 본문에 남긴다. 계산 필수성이나 빈번한 편집 가능성이 높아 전투 설정 바에 숨기지 않는 편이 발견 가능성과 조작감에 유리하기 때문이다.

## 구현·검증 결과

선택한 가독성·조작감 개선을 `feat/calculator-responsive-audit` 브랜치에만 반영했다. 모바일에서는 실전 DPS 결과가 기본 스펙보다 먼저 나타나며, 상단 탭·테마 전환·전투 설정 진입점은 최소 44px 높이, 룬 초월 선택은 최소 32px 높이를 자동 검사한다. 2560×1440, 1440×1050, 390×844에서 수평 스크롤 없이 기존 UI 회귀와 새 모바일 인체공학 기준이 모두 통과했다.

`npm run verify` 결과는 린트 오류 0건, 73개 테스트 통과, Statements 99.01% / Branches 95.56% / Functions 100% / Lines 99.63%, 프로덕션 빌드·기본 E2E 성공이다. 참조 프리셋 비교는 현재 최신 main의 계산 기준에서 -1.40%, +3.34%, +7.64%, +2.02%, +5.25%였고 모두 ±10% 이내다. 이 브랜치는 사용자 요청에 따라 main에 병합하거나 GitHub Pages로 배포하지 않는다.
