# 시안형 UI 재설계 실행 명세

## 1. 목표와 고정 원칙

본 작업의 목표는 종합 계산기·룬 교정실·보석 세공실·인장 설정실을 첨부 시안과 같은 **고밀도 데스크톱 작업공간**으로 구현하는 것이다. 계산 엔진, 스킬 계수, 마을 공격력 계약, 룬·보석·인장 산식은 변경하지 않는다. 모든 개선은 표시 계층, 정보 구조, 접근성, 상태 표현에 한정한다.

> **실전 DPS 결과는 우측 상단의 일반 문서 흐름에만 배치한다.** `position: sticky`·`fixed`·스크롤 추적 동작을 사용하지 않는다.

## 2. 첫 화면 정보 구조

| 영역 | 시안 기준 | 구현 기준 | 첫 화면 포함 여부 |
| --- | --- | --- | --- |
| 상단 헤더 | 제목과 4개 탭이 한 줄에 정렬 | 제목, 테마 토글, 4개 탭을 단일 탐색 헤더로 압축 | 필수 |
| 좌측 주 입력 | 핵심 스펙, 시즌 패시브, 스탠스, 전투 조건 | 핵심 스펙 8개와 시즌 패시브·스탠스·전투 시간·사이클만 노출 | 필수 |
| 우측 결과 | 실전 DPS, 적용 공격력, 확률, 룬 10개, 세부 연산·프리셋 | 결과 패널을 최상단에 놓고 룬 10개를 5×2 그리드로 배치 | 필수 |
| 부가 설정 | 조건부 버프·가동률 조정, 보조 스탯 | 좌측 개폐형 플로팅 바로 이동 | 선택 시 노출 |

첫 화면은 2560×1440 기준에서 주 입력·DPS 결과·룬 세팅·세부 연산·프리셋 비교가 한 화면에 보이는 것을 목표로 한다. 화면 폭이 1536px 미만이면 카드 열 수만 축소하며, 핵심 정보 순서는 유지한다.

## 3. 좌측 개폐형 플로팅 바

플로팅 바는 화면 왼쪽 중앙에 작은 세로 탭으로 표시한다. 탭을 누르면 왼쪽에서 고정 폭 패널이 열리고, 조건부 룬·가동률·밤의 축복 가동률·보조 스탯을 조정할 수 있다. 패널은 배경 오버레이 없이 열리며, 바깥 영역을 클릭하거나 닫기 버튼·Escape 키를 누르면 닫힌다. 모바일에서는 하단 시트가 아니라 일반 접이식 섹션으로 전환한다.

| 상태 | 시각 처리 | 상호작용 |
| --- | --- | --- |
| 닫힘 | 왼쪽 모서리의 세로 탭과 조절 아이콘만 노출 | 클릭·Enter·Space로 열기 |
| 열림 | 폭 360px, 내부 독립 스크롤, 현재 조정 수치 배지 노출 | 닫기·Escape·바깥 영역 클릭 |
| 활성 조건부 없음 | "조건부 룬 없음" 안내와 밤의 축복 가동률만 노출 | 입력 경로는 유지 |

## 4. 룬 교정실 상태 색

룬 교정 테이블은 행 전체와 고정된 첫 열에 동일한 상태 배경색을 적용한다. 장착 상태가 가장 높은 우선순위를 가지며, 그 다음은 누락·수정·기본 일치 순이다.

| 우선순위 | 상태 | 행 배경 | 좌측 강조선 | 상태 배지 |
| --- | --- | --- | --- | --- |
| 1 | 장착 중 | 연한 에메랄드 | 에메랄드 4px | 장착 중 |
| 2 | JSON 누락 | 연한 로즈 | 로즈 4px | 누락 |
| 3 | 수동 수정 | 연한 앰버 | 앰버 4px | 수정됨 |
| 4 | 기본 일치 | 연한 슬레이트 | 슬레이트 4px | 기본 일치 |

## 5. 설정실별 구현 기준

| 탭 | 첫 화면 구조 | 상태 표현 |
| --- | --- | --- |
| 보석 세공실 | 세공 핵심값 8개 + 특수 보석 효과 카드, 무기·장신구 대형 블록, 나머지 장비군 3열 | 완료·미완료·특수 보석 효과를 즉시 식별 |

| 인장 설정실 | 4개 환산 요약 카드, 5×2 인장 슬롯, 선택 인장 세부 조정 | 별·푸른 달·붉은 달 유형 색상 |

## 6. 필수 검증

1. 2560×1440, 1440×1050, 390×844에서 수평 넘침이 없어야 한다.
2. 2560×1440 첫 화면에서 종합 계산기의 핵심 입력·DPS 결과·룬 세팅이 동시 노출되어야 한다.
3. 실전 DPS 결과의 모든 조상 요소는 `position: sticky` 또는 `position: fixed`가 아니어야 한다.
4. 플로팅 바는 열기·닫기·Escape·바깥 영역 클릭이 동작해야 하며, 가동률 변경 후 DPS가 갱신되어야 한다.
5. 룬 교정실은 장착 중 룬 행에 에메랄드 배경과 강조선을 적용해야 한다.
6. `npm run lint && npm run test:coverage && npm run build`, `node scripts/compare_latest_reference_presets.mjs`, 브라우저 E2E를 모두 통과해야 한다.

## 7. 컴포넌트 책임과 구현 순서

| 순서 | 대상 파일 | 변경 책임 | 계산 영향 |
| --- | --- | --- | --- |
| 1 | `MainCalculatorTab.jsx` | 첫 화면 2열 비율, 핵심 입력 배치, 결과·룬·세부 연산의 첫 화면 순서 | 없음 |
| 2 | `StatsInput.jsx` | 핵심 8개 스펙과 상세 보조 입력의 분리, 시즌 패시브 압축 | 없음 |
| 3 | `ConditionalPanel.jsx` | 플로팅 바 안에서 재사용 가능한 조건부·가동률 조정 본문 | 기존 콜백만 사용 |
| 4 | `Calculator.jsx` | 플로팅 바 열림 상태, Escape·바깥 영역 닫기, 탭 헤더 정렬 | 없음 |
| 5 | `RuneAuditDashboard.jsx` | 행 상태 우선순위와 첫 열 배경 동기화 | 룬 값 편집 로직 유지 |
| 6 | `GemStonePanel.jsx`, `SealControlPanel.jsx` | 요약 카드 밀도·그리드·상태 강조 정렬 | 보석·인장 계산 경로 유지 |
| 7 | `scripts/ux-ui-check.mjs` | 첫 화면 요소 위치, 플로팅 바 상호작용, DPS 갱신, sticky 부재 자동 검사 | 검증 전용 |

구현 중 계산 관련 파일을 수정하지 않는 것을 기본 원칙으로 한다. 불가피하게 계산 연동 인터페이스를 수정할 경우에는 관련 회귀 테스트를 먼저 추가하고, 외부 DPS 프리셋 비교와 스프레드시트 마을 공격력 계약 테스트를 다시 실행한다.
